# CPU-only dependency set for CI and for container builds.
#
# Same application dependency set as requirements.lock.txt, with the CUDA payload
# removed and the torch stack repinned to CPU builds.
#
# Install with:   pip install -r requirements-ci.txt        (no --no-deps needed)
#
# Used by .github/workflows/tests.yml and by the Dockerfile. Verified: this file
# resolves cleanly under pip's resolver, unlike requirements.lock.txt.
#
# WHY THIS RESOLVES AND THE LOCK FILE DOES NOT
# requirements.lock.txt cannot be solved by pip: whisperx 3.8.6 pins
# torch~=2.8.0, torchvision~=0.23.0 and torchcodec<0.8.0, while the dev machine
# carries torch 2.11.0, torchvision 0.26.0 and torchcodec 0.16.0. This file pins
# a set satisfying EVERY constraint at once:
#
#     torch       2.8.0+cpu     whisperx ~=2.8.0     pyannote >=2.8.0
#     torchaudio  2.8.0+cpu     whisperx ~=2.8.0     pyannote >=2.8.0
#     torchvision 0.23.0+cpu    whisperx ~=0.23.0    (unconstrained)
#     torchcodec  0.7.0         whisperx >=0.6,<0.8  pyannote >=0.7.0
#
# REMOVED vs the lock file: 29 nvidia-* CUDA wheels plus cuda-bindings,
# cuda-pathfinder, cuda-toolkit and triton — inert without an NVIDIA GPU, together
# about 5 GB. Two of them return as transitive dependencies and cannot be avoided
# while whisperx is present: triton (whisperx requires triton>=3.3.0 on linux
# x86_64, about 600 MB) and setuptools (via ctranslate2).
#
# The CPU wheels are pinned with explicit "+cpu" local versions, which exist only
# on the PyTorch CPU index, so the source is unambiguous even though PyPI is also
# searched.
#
# SCOPE: this is the application set, not just what the test suite imports. It is
# deliberately not trimmed to the test closure, so the Docker image and CI use the
# same packages and a broken install is caught in one place.
#
# NOTE: the torch version here is 2.8.0 rather than the dev machine's 2.11.0. That
# is deliberate — it is the version both ML libraries agree on. The application
# only uses torch.from_numpy(...).unsqueeze(0), so the difference is immaterial.
# requirements.lock.txt remains the exact record of the dev machine.
